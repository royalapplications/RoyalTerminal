# Observing a foreground job

The Rex event reference distinguishes a terminal's child exiting from a change in its foreground process. RoyalTerminal now emits `terminal.process_changed` on **Linux PTYs** using the event's documented `generation`, `foreground` and `ancestors` fields. This is independent of a client being attached or a process producing output. Sources: [Rex events](https://www.superlogical.com/rex/docs/reference/events) and [Linux procfs](https://docs.kernel.org/filesystems/proc.html).

The first verified observation has generation 1. A change in foreground process group, leader identity, birth time or command name advances the generation. An unchanged sample does not. The metadata sequence orders this event among other block events; the generation is not a journal cursor. Session and global journals keep their existing independent cursors and authorization. `events --json` and Lua callbacks expose the three fields directly in the nested block-event payload. A generation with no verifiable leader has `foreground: null`. An absent initial observation is not a synthetic null-to-null transition.

The kernel foreground **process group** is the authority. The event identifies its group leader when verifiable, not a guessed descendant, the last spawned process, or every member of a pipeline. Ancestors are nearest-first, stop at the PTY child or the tty/session boundary, and are limited to 12 records. Only PID and kernel command name are published. No argv, environment, cwd lookup, process signals, lease acquisition, or terminal writes occur. Names are untrusted text.

A factory starts one sampler when its first Linux PTY is registered. Each tick checks at most 32 PTYs, rotating across them; the nominal interval is 250 ms and ticks do not overlap. Procfs reads occur outside the parser lock. The sample verifies the root/leader identities and rechecks the tty foreground group before publishing. Block closure and process exit exclude later publication. The existing metadata retention and slow-reader limits apply; ancestry is included in the retention charge. This is an observation service, **not kernel tracing**: short-lived intermediate foreground jobs may be missed. Pipes and unsupported operating systems emit no invented foreground transitions. Existing direct process inspection remains available according to host capabilities.

`scripts/workspace/smoke-foreground.py` transfers a real PTY between two process groups, then returns it to its original owner. Its barriers allow an HTTP observer and a live Lua callback to register before the handoff; it also compares the raw and NDJSON events and verifies the terminal exit ordering.
