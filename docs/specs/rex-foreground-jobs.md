# Observing a foreground job

The Rex event reference distinguishes a terminal's child exiting from a change of foreground process. RoyalTerminal emits `terminal.process_changed` on **Linux and macOS PTYs** using `generation`, `foreground` and `ancestors`. Observation does not require an attached client or output from the job. Sources: [Rex events](https://www.superlogical.com/rex/docs/reference/events), [Linux procfs](https://docs.kernel.org/filesystems/proc.html), [Darwin proc_info.h](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/proc_info.h).

The first verified observation has generation 1. Changing foreground group, leader identity, birth time or command name advances the generation. An unchanged sample does not. The metadata sequence orders this among other block events; the generation is not a journal cursor. Session and global journals retain independent cursors and authorization. `events --json` and Lua callbacks expose the three fields directly in the nested block-event payload. An observed group with no verifiable leader has `foreground: null`. An unavailable initial observation does not synthesize a transition.

The kernel foreground **process group** is authoritative. The reported process is its group leader when verifiable, not a guessed descendant or every pipeline member. Ancestors are nearest first, stop at the PTY child or the tty/session boundary, and are capped at 12. Only PID and kernel command name are published. No argv, environments, process signals, control leases, or terminal writes are involved. Treat names as untrusted text. The typed `process` method uses the same platform reader for on-demand inspection.

Linux reads `/proc/<pid>/stat`; the parser locates the final parenthesis before indexing numeric fields, since `comm` can contain spaces, newlines and parentheses. macOS reads the public `PROC_PIDTBSDINFO` structure with `proc_pidinfo`, and the session ID with `getsid`. The SDK compile-time assertions check every field offset used by the managed binding. Both readers check the process birth value and re-read the controlling terminal association and foreground group before publishing. The root and observed leader cannot be treated as a single atomic snapshot of the entire OS process table.

There is one timer per factory with registered Unix PTYs, not one timer per viewer. A tick checks at most 32 terminals on a rotating basis; the nominal interval is 250 ms and ticks do not overlap. OS queries occur outside the parser lock. Block closure and process exit exclude later publication. Ancestry counts against the existing metadata retention budget. This is observation, **not kernel tracing**: short-lived intermediate jobs can be missed. Pipes, Windows/ConPTY and other unsupported hosts do not emit invented job transitions.

`scripts/workspace/smoke-foreground.py` transfers a real PTY between two process groups and returns it to its original owner. Barriers allow HTTP and live Lua observers to register before the handoff. The test checks ordered generations and ancestors, read-only and cross-session authorization, scope projection in NDJSON and final exit ordering. The dedicated protocol workflow runs it against real Linux and Darwin brokers, not an emulated `/proc` tree.
