# Workspace implementation review · 2 November 2026

Baseline: `c4653b9`. Scope: the complete experimental PR inventory, focused manual review of its high-risk paths, executable regression tests, and visual inspection of the RoyalTerminal clients. The scope is not an independent security certification or proof of Rex wire or pixel compatibility.

| Area | Finding and change | Check |
| --- | --- | --- |
| Terminal input | A controller could start an HTTP request while authorized, lose its grant while the body was being read, and still reach input dispatch. Revalidate the original grant and cancellation after the read. | `InputAdmissionTests` revokes inside the request stream; neither revoked controllers nor readers reach dispatch. This does not retract any bytes already admitted. |
| Credential transport | The shared managed endpoint accepted plaintext HTTP to remote DNS names and LAN addresses. Enforce HTTPS outside literal loopback and localhost before building authenticated HTTP or WebSocket requests. The Unix socket origin remains valid. | `CredentialTransportTests` and local broker integrations. |
| Peer routes | A full 515-byte buffer could be trimmed and accepted even when more bytes followed. Accept a complete 32–512 byte printable credential with a single optional LF/CRLF. Reject oversized files before trimming, clear scratch data, and sanitize errors. | `PeerCredentialFileTests` includes the maximum valid size, wrong terminators, and appended bytes. |
| Status inspection | A status scan used to materialize an entire session for each terminal. Look up a block in its owning session instead. | `ScopedLookupTests` covers foreign, moved, and closed blocks. This removes redundant work; no measured speedup is claimed. |
| Navigation and attention | Polling used to replace focused controls. Reconcile tabs and sessions by identity and support arrows, Home, and End. Show background tab status from the server's OSC 7501 counts. Use spare polls to check other visible sessions in oldest-first order, including sessions not previously opened; never fan out per terminal or per workspace. Badges only display a summary matching the currently known structure revision. | `shell-navigation`, `attention-budget`, and the real-process browser scenario. |
| Layout operations | Shelf restoration captured old revisions; follow-up shell creation could consult the new selection instead of the intended window. Capture target IDs and evaluate the shelf revision when Restore is invoked. | Existing placement and real-shell browser scenarios. |
| Browser revocation | Polling after token revocation could leave old terminal buffers and a share dialog on screen. Dispose pane caches, close dialogs, remove sensitive content, and clear credentials on 401. A transient connection error does not sign the viewer out. | Revoke an observer with a modal open. Assert no terminal DOM, open modal or password remains. |
| Browser interface | Make the server, active session, tab strip, and current terminal the main hierarchy. Limit palette results to a scrollable region on narrow screens; preserve the query and selection. Local and remote sidebar actions now use the same control. The phone picker confines focus while open and restores it on dismissal. | Real Chrome at desktop and phone dimensions, plus remote focus and typed Lua palette regressions. |
| Terminal input vs. observation | The original phone capture had live-looking send-key buttons even for an observer. Bind the toolbar to the actual live lease: controllers get terminal keys, observers get **Page up**, **Page down**, and **Latest**. Reading never uses the input path. Touch arrows respect application-cursor mode; keyboard focus reporting uses xterm's public mode flag. | `terminal-toolbar.test.mjs` covers revoke/restore, retained button identity, and both VT cursor encodings; the phone browser test uses the actual read controls. |
| Native clients | A wide desktop overview now exposes windows as tabs, switching to a compact picker below 700 DIPs without changing the selected identity. Connection parameters and optional ID entry are separated from terminal content. Native phone status has its own row and buttons have a 44-DIP minimum. | `AdaptiveTabTests`, desktop observer/scroll/zoom and phone headless suites. |

## References and differences

Rex's [program-status documentation](https://www.superlogical.com/rex/docs/build/program-status) describes background tab indicators and the session picker; its [keyboard documentation](https://www.superlogical.com/rex/docs/customize/keyboard-shortcuts) describes configured bindings and action discovery. The [product study](rex-product-research.md) documents the public interface examples. The layout follows those behaviors; RoyalTerminal retains its own identity, explicit permission states, and controller/observer semantics. Touch cursor and focus sequences follow the [pinned xterm.js public mode contract](https://github.com/xtermjs/xterm.js/blob/6.0.0/typings/xterm.d.ts).

## Validation and reproduction

On a matching PR there is still **one Ubuntu experiment runner**. A tip commit subject containing `[workspace-ui]` opts that same runner into the source inventory and installed-Chrome checks. `scripts/workspace/review-source.py` inventories every changed path against the PR base, verifies supported script/XML/JSON formats without executing those files, and records unparsed formats as *inventory only*. The C# projects are built by the managed tests, not by that syntax script. YAML, Markdown, other deployment conventions and private integrations are not automatically certified by parsing a change list.

The browser fixture launches real PTYs on a local Kestrel broker. Desktop panes show repo paths, git history, and runtime information; the Review tab receives a real permission request emitted by a child. A 390-pixel observer verifies that reading changes neither terminal input authority nor process existence. Screenshots, `layout.json`, `source-review.json`, browser output, and seven TRX files are in the run artifact. Locally build the streaming assets and the Release server as documented in the server README, then run `npx playwright test workspace-review.spec.mjs` in the server directory. Set `WORKSPACE_REVIEW_EVIDENCE` to retain images.

The full browser/Wasm or cross-OS profiles remain opt-in. Physical iOS/Android handsets, live push and Tailscale providers, FreeBSD and production signing identities were not exercised by this review.
