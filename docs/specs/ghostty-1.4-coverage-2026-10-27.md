This inventory covers all 265 bullets in the full changelog, localization, and package-maintainer sections, all ten security advisories, the highlight/breaking/deprecation sections, and the libghostty integration notes. Financial/project-roadmap prose is not a terminal feature.

The initial read-only audit examined RoyalTerminal `360d3ccea91545087879ce6457ec78c19280e77b`, whose native pin was `246f702876b924a1cb7cade1e99274d1470302fc`. The update target is `4a4fc017940bec38c93b278c10c6a18c591f3e63` (1.4.1-dev immediately after 1.4.0). ## How to read the matrix

- **Implementation located** means relevant source and tests were located; it does **not** mean this audit executed those tests, proved every clause, or validated the newly built native runtime. Explicitly identified defects override that classification.
- **Review / Partial** requires the stated verification or missing layer. An API/parser is not proof of desktop integration, and test filenames alone are not an acceptance result.
- **Native** means the upstream library fix is inherited by rebuilding the new pin. Managed and shared-host behavior is stated separately.
- **App gap / Separate app feature** means the behavior is not established in RoyalTerminal. These are recorded differences, not claims of completion. Most predate the October 9 pin and are not automatic scope additions to the current preview request.
- **App-only** identifies an implementation/configuration/package specific to Ghostty's separate Swift/AppKit or GTK application which RoyalTerminal does not link. Where the user-visible feature is portable, the table records the corresponding separate feature/review rather than declaring it universally inapplicable.

No Ghostty performance multiplier in the release notes is a RoyalTerminal measurement. Native and managed performance must be measured with the project's own workload and runtime.

## Actionable new-pin work

1. Rebuild native overlays/packages with Zig 0.17 and update changed public bindings; stale native binaries cannot validate this update.
2. **Implemented and focused tests passed:** Kitty snapshot storage, image/frame payloads, page placements, pending animation state, transfer continuation, unknown records and PAGE capacity validation. Native snapshot wrapper progress/image-budget APIs are updated; there is no separate `GhosttyVtProcessor` snapshot adapter to migrate. See the tested snapshot evidence below.
3. Managed-core audit confirmed missing or divergent DECXCPR, CSI 19t, fixed-reset ANSI mode reports, DECSTR ISO protection reset, CUB/BS left-margin handling, HPR/VPR origin handling, HPA alias, prompt ED2 history preservation, cancellation/abort and C1 restart behavior, and OSC 7501 capability/raw-ID behavior. These are implementation work, not completed by the existence of older broad tests.
4. Validate new VT export preservation of links, blank styled cells, and trailing rows; wide selections across page boundaries; latest Kitty transfer interruption and parser cancellation.
5. Host inspection already finds the intended order for prompt release-before-click, VT resize-before-PTY resize, and IME cursor rectangle updates. Focused regressions remain necessary; this audit has not found a new host failure in those paths.

Pre-existing desktop differences worth preserving explicitly: OSC 52/5522 callback contracts exist in both backends but no production assignment of `ClipboardReadCallback`, `ClipboardWriteCallback`, or `ClipboardWriteRequestCallback` was found. The default selection service handles text only. Native clipboard write limit is hardcoded to 16 MiB, not the release's 64 MiB application default. Copy-on-select remains a Boolean; the app exposes a line history limit rather than independent byte/line limits. These are not solved merely by updating libghostty.

## Tested snapshot delta

The managed engine now reads and writes Ghostty record tags 8–10: image metadata and reserved pending storage before READY, incremental image/frame pixels afterwards, and history placements adjacent to their owning PAGE. Relative descendants follow their root's page in parent-before-child order, including anonymous placement namespaces and inactive screens. Invalid metadata/placement identities are dropped as upstream does; structural truncation, checksum failure, and resource limits still fail the decoder. Late payloads use stable transmission tickets, so replacement, deletion, reset or alternate-screen retirement cannot attach old pixels to a new image.

Export follows upstream payload priority: the active viewport's displayed frames first, then other visible frames; history image pixels with the newest page that needs them; inactive viewport images and unplaced images last. A sorted array with indexed ranges avoids rescanning every image for each history page. Import publishes a completed displayed frame immediately and starts scheduling a running animation only when all its frames have arrived. In-progress raw, zlib, PNG, and zlib-compressed PNG transfers survive native→managed→native snapshots, including animation loads addressed by image number.

Validation on the rebuilt macOS arm64 native runtime: **46 tests passed, none skipped**, using `ManagedKittySnapshotTests`, `ManagedKittySnapshotValidationTests`, and `ManagedSnapshotGraphemePressureTests.HugeHintsDoNotReserveHugeBitmapOrMapStorage`. This includes all ten upstream Kitty/unknown-record golden fixtures; exact native placement identity, source rectangle and resolved geometry comparisons; nested history-relative chains, anonymous IDs and both screens; pending-frame ordering/visibility; zero/insufficient storage budgets; checksum and cumulative unknown-record budgets; malformed counts, image metadata and external placement ID zero; and stale pixel retirement. The broader Snapshot run also exposed older grapheme-allocation assertions and mode allocation regressions being handled by the managed-core review; this focused result is not presented as the full solution test result.

The wire contract is Ghostty `snapshot/kitty.zig` and `snapshot/snapshot.zig` at the new pin. Windows Terminal's SIXEL implementation and xterm.js's VT serializer do not define equivalent Kitty binary snapshot records. Managed host per-image/total-record limits remain explicit resource policies; they are not copied from untrusted source capacity hints. Snapshot v1 itself still omits glyph registrations and host selection, matching upstream's format rather than silently inventing additional records.

## Highlights, breaking changes, and deprecations

Highlights repeat the detailed requirements: macOS27 R133; Kitty animation/relative placement R064–R066/R085–R092; memory/performance R001/R014–R021/R148–R149/R224; GTK renderer R207–R208; clipboard R067; split dragging R008/R206; VT conformance R068–R075/R093–R117; SSH R120–R124. This avoids counting repeated marketing descriptions as additional implementation.

Breaking/deprecated configuration is explicitly covered by R002 (renamed `scrollback-limit`/new line and byte limits), R003 (copy-on-select enum and macOS default), R145 (macOS prompt-navigation defaults), and R221 (GTK tab/prompt shortcuts). RoyalTerminal does not load Ghostty's configuration file, so its own saved profiles require an intentional migration only if corresponding settings are adopted. No removal timeline is inferred.

## Libghostty integration checklist

| Requirement in the prose update | RoyalTerminal mapping |
| --- | --- |
| Complete terminal emulator C API rather than parser-only API | RoyalTerminal wraps terminal state, encoders, selection/search, snapshot and effects. Latest ABI changes require wrapper synchronization and native/managed conformance tests; upstream explicitly still considers ABI unstable. |
| macOS/Linux/Windows MSVC+GNU/FreeBSD/Android/iOS/WASM targets | These are upstream build targets, not a promise RoyalTerminal ships every platform. Existing runtime packages/workflows define RoyalTerminal's supported distribution. Cross-target native CI must compile the new Zig pin. |
| CMake/Nix/xcframework/source tarball/pkg-config integration | RoyalTerminal uses its own Zig build overlays and runtime packages. Alternate upstream packaging paths need not be substituted for a working supported build. |
| No libc++ requirement; freestanding build option | Upstream linking improvement inherited where RoyalTerminal build mode supports it; confirm actual runtime dependency lists rather than assume all existing overlays are freestanding. |
| Current API docs and 30+ language examples | Integration references, not standalone terminal features. Native enum/layout/export checks and consuming tests remain required. |
| Planned final ABI break / future libghostty1.0 | Roadmap, not released capability or a reason to claim compatibility with an unreleased1.0. Pin exact source and document current ABI. |
