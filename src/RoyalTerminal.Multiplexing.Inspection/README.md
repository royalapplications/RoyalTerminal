# Experimental terminal inspection

This package decorates an existing `ITerminalTransportFactory`. The broker still
owns transport lifetime. Each resulting `InspectingTerminalTransport` maintains
canonical managed VT state even without an attached presentation client. It
reuses `BasicVtProcessor`, existing snapshot formatters, and OSC 7501 state.

```csharp
InspectingTerminalTransportFactory inspecting = new(existingFactory);
await using MultiplexerBroker broker = new(inspecting);
MultiplexerSessionDescriptor session = broker.CreateSession("work");
// Use a distinct options object for every live block.
MultiplexerBlockDescriptor block = await broker.AddBlockAsync(session.Id, "shell", options);
if (inspecting.TryGetInspection(options, out InspectingTerminalTransport? terminal))
{
    string screen = terminal.Capture(TerminalSnapshotExportFormat.PlainText);
    string title = terminal.Title;
    string workingDirectory = terminal.WorkingDirectory;
    IReadOnlyList<TerminalProgramStatus> status = terminal.ProgramStatuses;
}
```

The factory deliberately uses options **reference identity**. The host can map
the returned block ID to the resolved inspection instance. Equal-valued options
for different terminals never alias. Reusing the same options instance before
its transport is disposed is rejected. Disposal unregisters the instance.

## Query authority and ordering

The server terminal answers device/status/capability queries. Clients rendering
the forwarded output must suppress automatic query replies, while continuing to
send genuine keyboard, paste, and pointer input. Attaching additional observers
therefore does not multiply replies. Query replies generated during startup are
queued until the underlying transport starts. Replies are sent outside the
parser lock, allowing transports to deliver synchronous or cross-thread output.

Screen mutation, metadata/status reads, snapshot capture, and output publication
share a lock. Resize updates the canonical screen before asking the transport
to redraw. Transport calls themselves run outside the parser lock. Consumers
of synchronous output/exit events must return promptly. Providers remain
responsible for serializing concurrent input writes, as in ordinary terminal
sessions. A response queue overflow or write failure is retained in
`ResponseError`; output remains inspectable.

History has row and logical page-byte limits. Dimensions also have a visible-cell
limit so independently reasonable width and height values cannot produce an
unbounded product. The byte quota is a terminal-page budget, not a strict CLR
heap limit. Graphics decoding and host effects are intentionally disabled in
this inspection plane: it installs no file/shared-memory reader, clipboard,
notification service, or host window-resize handler. Titles, working-directory
values, and status text are untrusted plain text. A working directory is retained
as reported and is never opened or resolved on the server filesystem.

## Terminal reference decisions

Reviewed before implementation on 2026-10-30:

- [xterm.js InputHandler](https://github.com/xtermjs/xterm.js/blob/master/src/common/InputHandler.ts):
  DSR/CPR responses are generated by terminal state and delivered through its
  input response path. Replaying the same output into multiple authoritative
  terminals would generate multiple replies.
- [Windows Terminal AdaptDispatch](https://github.com/microsoft/terminal/blob/main/src/terminal/adapter/adaptDispatch.cpp):
  device status/cursor position are terminal-state queries; title and working
  directory are host metadata updates.
- [Ghostty stream dispatcher](https://github.com/ghostty-org/ghostty/blob/main/src/terminal/stream.zig),
  inspected at the repository's pinned submodule: title UTF-8 validation, OSC 7,
  and clipboard are distinct effects dispatched to a host. Inspection reuses
  RoyalTerminal's corresponding managed behavior and supplies no clipboard or
  filesystem capability.

The wrapper changes ownership and host policy, not VT sequence parsing.
Snapshot-format parity remains the responsibility of the existing managed VT
engine. PowerShell invocation/startup is unchanged; this package wraps transport
options without modifying commands, environments, or shell selection.
