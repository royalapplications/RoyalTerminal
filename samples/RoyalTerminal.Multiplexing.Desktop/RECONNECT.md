# Native reconnect semantics

Manual **Attach** selects a block and creates a fresh parser. Automatic reconnect is different: after an established connection fails unexpectedly, the desktop controller keeps the existing `RemoteTerminalControl`, `TerminalSessionService`, VT processor and screen. It tears down the failed socket, flushes the control’s queued bytes on the dispatcher, and reopens the same transport identity with `after=LastSequence`. No input, resize, or partially sent paste is retransmitted. Options and credentials come from the original attachment, never from text the user may have since typed into the connection form.

There are up to six transient-error attempts with capped exponential delays. An orderly close is **not** retried: it may be an administrator deliberately disconnecting a controller. Explicit detach/window close cancels retry; process exit stops it. Protocol errors, replay gaps, and permission/lease denials require an explicit decision. A gap does not silently replace the existing parser with an inconsistent view. When the host's optional cold replay tier has the bytes, the same wire protocol can recover the suffix even after hot-history eviction.

The headless acceptance test starts a CSI sequence before a network failure and finishes it after reconnection. It verifies the actual cursor-positioned glyph on the **same** screen and processor, verifies the resumed cursor, and ensures a keystroke sent before failure does not appear on the replacement socket. This covers parser continuity rather than simply checking that two strings reached an event callback.
